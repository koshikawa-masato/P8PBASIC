# NEOMSC 契約メモ（器が満たすべき外部インターフェース）

作成: 2026-11-17 / 方法: z80dis によるフロー追跡逆アセンブル
（カバレッジ 4233/4352 バイト）。実測と推定を分けて記す。
一覧表の根拠は本文末尾の出典。

## 基本情報（実測）

- ロードアドレス **0x9800**、サイズ 0x1100（4352 バイト）。
  根拠: 初期化コードが自分自身の領域内のアドレス（0x994D 等）を
  フック先として書き込むこと、CLEAR ,&H97FF で BASIC 側が
  0x9800 以降を保護していること。
- エントリは 0x9800。初期化後に RET で BASIC へ戻る。
- 先頭 3 バイト（0x9801–9803）はコードではない（データ/署名領域）。

## 初期化（0x9800–0x9850、実測）

1. DI の後、RAM ベクタ 3 つに JP 命令（0xC3）を書き、飛び先を設定:
   - 0xEEA1 → 0x9E5C
   - 0xEEA4 → 0x994D
   - 0xEEA7 → 0xA6DB
2. ワークエリアへ書き込み: (0xE6B9)=0xFF、(0xE6B4)=0xE8。
3. BC=0x5019 で CALL 0x6F6B（外部ルーチン、役割は未確定）。
4. サウンドボードII探査: OUT (0xA8),0xFF → IN (0xA9) が 1 なら有り。
   無い場合は YM2203 用にコード内 6 箇所へ 0xAC を書き込む
   （自己書き換え: 0x9B95, 0x9BC9, 0x9BD2, 0x9AD9, 0x9AE3, 0xA82D）。
5. EI、RET。

## フックベクタ 3 つ（入口コードからの観察）

| ベクタ | 先 | 入口の振る舞い（実測） | 役割の推定 |
|---|---|---|---|
| EEA1 | 9E5C | A をポート 0x31 と (0xE6C2) へ書き、0xAA15 に JP 命令コードを置いて戻る | PMD 連携（割り込み連鎖/ドライバ状態） |
| EEA4 | 994D | A が 0x11 未満なら E=A として 0x9C01 / 0x9C05 を呼ぶ（テーブル駆動） | 番号 0–16 の機能ディスパッチャ（拡張関数群か） |
| EEA7 | A6DB | HL を逆向きにたどる XOR ループ、0xA82B を DE=0x21 / 0xA0 で呼ぶ | ディスク読み取り系（文ディスパッチの可能性も） |

どのベクタが FFDD/FFDE/FFDF のどれに対応するかは、器での動的トレースで確定する。

## BASIC 側サービスへの依存（器がトラップして提供するもの）

- **RST 8（inline バイト付き）**: 使われるのはサービス **0x2C のみ**、
  27 箇所。引数読み取り部に集中。意味は動的トレースで確定する
  （式評価系と推定）。
- **ディスクサブシステム ROM ルーチン**（公開資料で同定）:
  - CALL 0x37C9 ×2（PUTCOM=0x37CC の直前エントリ）
  - CALL 0x37D2 ×7 = PUTDAT（A をサブシステムへ送信）
  - GETDAT=0x3847 への直接呼び出しは検出されなかった（ポート直読みか）。
- その他の外部 CALL/JP（要同定、動的トレース対象）:
  0x00C1, 0x01B6, 0x029A, 0x03B3, 0x06C9, 0x11D3, 0x1796, 0x18A3(×6),
  0x193E, 0x1B9D, 0x2256, 0x37C9, 0x56CC, 0x6000, 0x610A, 0x6F6B,
  0xF6E6（JP）, 0xA90D（RAM スロットの可能性）。
  一部はデータ領域の誤読の可能性がある。

## ディスクアクセスの実像（公開資料＋実測）

PC-88 のディスクは独立したサブシステム（サブ CPU＋FDC）で、メイン側とは
8255 経由（ポート FC=受信データ、FD=送信データ、FE=ハンドシェイク、
FF=8255 制御）でコマンドプロトコルを話す。NEOMSC は ROM ルーチン
（PUTCOM/PUTDAT）とポート直接操作（IN (0xFE) ×18、OUT (0xFF) ×26 等）
の両方を使う。器はこの 8255＋サブシステムをポートレベルで再現し、
コマンド（02h リードデータ＋03h センドデータ等）を D88 イメージで
処理すればよい。FFDE のセクタ読みはこの経路で NEOMSC 自身が行う。

## PMD との接続（実測）

- NEOMSC から PMD 領域への呼び出し: CALL 0xAA03 / 0xAA06 / 0xAA09。
- 0xAA15 に JP 命令コードを設置（飛び先は PMD 側/別ルーチンが設定）。
- PMD 本体はディスク予約領域から 0xAA00 へ FFDE で読み込まれる
  （MENU.ALP 260 行）。

## ワークエリア共有（実測）

- 0xE6C2: 読み書き 20 箇所。ドライバ状態バイト（BASIC 側 PEEK 対象の
  &HAA20/&HAA21 とは別。こちらは BASIC ワークエリア側の状態）。
- 0xEC41: 読み ×3。0xF416: 書き ×1（テキスト VRAM ポインタ近傍）。
  0xFE69: 書き ×1。

## ポート使用（即値、被覆コード内の実測）

- OUT: 0x31(×16), 0x32(×8), 0x34(×4), 0x35(×8), 0x5F(×4), 0xA8,
  0xE6–0xEB, 0xF8, 0xFC–0xFF
- IN: 0x32(×8), 0x46, 0xA9, 0xE8, 0xE9, 0xF8, 0xFC–0xFE(×18)
- 0x34/0x35 は CTC（タイマ割り込み＝演奏クロック）系と推定。
  0x31/0x32 は割り込み制御・サブ CPU 通信系と推定（要同定）。

## 器への要求（まとめ）

1. Z80 コア（superzazu/z80）＋ 64KB 共有メモリ（BASIC の PEEK/POKE と同一）。
2. BLOAD "NEOMSC",R で 0x9800 へロードし Z80 をエントリから実行、
   RET で BASIC へ復帰。
3. EEA1/EEA4/EEA7 ベクタ呼び出しをインタプリタ側から Z80 へ中継
   （XDD/XDE/XDF スタブと FF 関数が接続点）。
4. RST 8 (svc 0x2C) と外部 CALL 先をトラップし、ネイティブサービスで
   代行（ディスクは 8255 ポートモデル＋サブシステムコマンド処理）。
5. CTC 相当のタイマ割り込みで PMD を進める。ポート 0xA8–0xAB /
   0x44–0x45 を YM2608/YM2203（ymfm＋リズム音源）へ橋渡し。
